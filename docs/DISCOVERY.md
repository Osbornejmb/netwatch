# Local device discovery

Discovery is an opt-in convenience for reviewing Windows neighbor-table entries on the host's directly attached private IPv4 networks. Set `NETWATCH_DISCOVERY=1` to enable scheduled scans (five-minute interval); it is off by default. The collector reads `arp.exe -a` with shell execution disabled and literal arguments. Optional ICMP sweep is separately disabled by default and enabled with the launcher's ICMP discovery checkbox (`NETWATCH_DISCOVERY_ICMP=1`). It uses the shared eight-permit probe gate and fixed Windows probe helper. Scans are capped at 1,022 addresses; subnets wider than /24 are refused by default and a local `NETWATCH_DISCOVERY_MAX_PREFIX` setting can widen the allowed prefix down to /16, still subject to the sweep cap. No switch or router configuration is needed.

The host derives subnets from active non-loopback, non-link-local RFC1918 IPv4 interfaces and filters neighbor entries to those directly attached ranges. Results have a separate SQLite table and are shown in Discovered devices. Add to map requires an explicit action and current inventory revision. Added devices have monitoring disabled; ICMP authorization remains separately off. Ignore and unignore affect only discovery review state. Discovery errors preserve prior results. A device becomes Not seen after three successful scans omit it.

The loopback-only API provides `GET /api/v1/discovered?after=0&limit=100`, bodyless `POST /api/v1/discovered/scan-now`, and `POST /api/v1/discovered/:id/{ignore,unignore,add-to-map}`. Write requests require `X-NetWatch-Write: 1`; add-to-map includes `baseRevision` and uses the existing inventory conflict check. Results are paginated (maximum 200). The v5 migration is transactional; discovery rows are retained for 30 days and included in SQLite backups.

This method cannot see every device. Wi-Fi client isolation, sleeping devices, randomized phone MAC addresses, and devices on other subnets or VLANs can hide or confuse entries. The neighbor table may contain only recently communicating devices. Treat names and addresses as untrusted hints. Do not treat discovery as authorization or as proof that a device is up or down.

Validation in this branch uses synthetic interfaces and fake neighbor output only. A real Windows home-network comparison remains unverified and must be performed by the owner on the approved network.
